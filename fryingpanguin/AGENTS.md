# Work-item scope, review and completion

- At item start, record a bounded acceptance checklist and validation
  plan. Only explicit user requirements and demonstrated defects may
  expand that checklist. Optional improvements belong in the backlog.

- Run proposal and selection stages once per work item. Exact user
  instructions already choose the requested behavior: label wording,
  colors and adjustments to existing tuning constants do not require
  another proposal or selection committee. Implement them directly,
  update the acceptance checklist and validate the affected behavior.

- Classify each follow-up by its own implementation scope, rather than
  inheriting the parent item's complexity. Local text/color fixes and
  explicit changes to existing tuning constants use one independent
  reviewer. New mechanics, persistence/migration, control contracts,
  architecture or uncertain interactions use five. Final acceptance
  requires 1/1 or 4/5, respectively.

- Return to selection only when implementation requires choosing a
  materially different design: new mechanics, additional offer types,
  changed save semantics, changed controls or expanded scope.
  Correcting defects within the selected design does not restart
  proposal or selection.

- Re-run checks affected by the change. Preserve earlier evidence for
  unaffected behavior, recording its source hashes and coverage.
  Label/color changes require relevant state and layout checks.
  Timing changes require actual cadence, modifier interactions and
  representative ordinary play. Repeat large progression cohorts or
  full browser matrices only when a concrete coverage gap or failure
  justifies them.

- Synchronize documentation before final validation, then freeze the
  candidate. Assign complementary checks to acceptance reviewers;
  share reproducible test evidence instead of requiring each reviewer
  to repeat the entire suite. Every reviewer assesses the whole item
  and independently verifies the evidence relevant to their findings.

- When the checklist passes, the required reviewers approve the
  current candidate and no acceptance blocker remains, immediately
  move the item to FINISHED-WORK-ITEMS.md and begin the next item.
  Do not add another polish, audit or documentation cycle before
  recording completion. Record nonblocking findings as follow-ups.
